# Orion audio

## Background music (HPA-168)

The four music tracks are original ElevenLabs Music v2 generations made from
project-authored prompts, without reference recordings. They are intended for
HPA-417's playback integration. Each is a 20-second, 22,050 Hz, 16-bit mono
PCM WAV, 882,044 bytes; the four total 3,528,176 bytes.

| File | Intended use |
| --- | --- |
| `music_map.wav` | Quiet navigation and menus |
| `music_build.wav` | Thoughtful preparation |
| `music_wave.wav` | Restrained combat pulse |
| `music_boss.wav` | Higher-tension boss ambience |

`music_provenance.json` records the prompts, model, generation IDs, source
checksums and chosen start time. Each 30-second MP3 was decoded to mono PCM
with FFmpeg 8.1.2; the retained decoded takes are in the gitignored
`assets/audio/music_sources/` directory. Keep a private backup of these files.
With those takes present, `python3 scripts/generate_music.py` checks their hashes
and reproduces the masters offline using a two-second overlap crossfade and a
peak target of 0.16 full scale (about -15.9 dBFS). The source recordings cannot
be regenerated byte-for-byte from prompts, and the script does not read or alter
the sound-effect sources. Run the following to check the shipped files and, when
source takes are available, their offline reproduction:

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
```

The generated tracks are subject to the generating account's
[ElevenLabs Music Terms](https://elevenlabs.io/music-terms). The generating
account owner has confirmed that the account's agreement permits distributing
the four mastered WAVs as tracked files in this public repository and
embedding them in the game release: under the Music Commercial Rights Table,
game use is covered while Orion qualifies as an Indie Game. Compiling or
distributing a music library from generated output is prohibited on
self-serve plans, so the decoded takes in `music_sources/` stay private, and
inclusion in this repository does not grant unrestricted redistribution
rights. Automated waveform checks do not establish musical quality,
masking, or native-player gaplessness. Listen on representative iOS and Android
devices in each context, with combat effects and across repeated loop seams,
before accepting the tracks.

`scripts/generate_feedback_audio.py` (Python standard library only); their bytes
are pinned by the Python contract test. The other 24 sound effects are Last Hearth
one-shots generated for Orion with **ElevenLabs Sound Effects**
(`eleven_text_to_sound_v2`) from project-authored prompts; no existing recording
or third-party sample was supplied. `sfx_provenance.json` is the single record of
each take's prompt, model, flow/node/session/generation IDs, download and decoded
source checksums, and the selected `duration` and `peak_db` used for mastering.

feedback layer already reference. The five new files are registered in

these assets change none of that.

## Sources and reproducible mastering

Each generated take was decoded once from the downloaded MP3 to 44.1 kHz 16-bit
mono PCM with FFmpeg and kept unprocessed under `assets/audio/sources/`. That
directory (and its `downloads/` MP3s) is gitignored and **not tracked in this
public repository**: the Sound Effects terms restrict making generated output
available as isolated audio files. Authorized maintainers obtain `sources/` (the
24 WAVs) from the project owner's private storage and place it at
`assets/audio/sources/` before regenerating.

From the repository root:

```sh
python3 scripts/generate_feedback_audio.py
python3 -m unittest discover -s scripts -p 'test_*.py'
```

Regeneration is offline and standard-library only: validate each source's
checksum and format against `sfx_provenance.json`, soften hiss with a 6.5 kHz
low-pass, remove DC, trim leading silence with 3 ms pre-roll, crop to the selected
`duration`, apply 3 ms attack / 25 ms release fades to zero, and normalize to the
selected `peak_db`. Every source is mastered and validated before any file is
written, so a corrupt source never overwrites known-good masters. The generator
rebuilds all 26 WAVs byte for byte; it does not call ElevenLabs or need FFmpeg.
Fresh AI generation is stochastic and spends credits, so it is not the
regeneration path. Without the private sources the public contract test still
checks every tracked WAV against `sfx_provenance.json` and `pubspec.yaml`; only
the byte-exact regeneration test is skipped, with an explicit reason.

The 26 sound-effect WAV paths are registered individually in `pubspec.yaml`.
Neither this README nor the source directory ships in the app bundle.

## Licensing and remaining review

`confirm.wav` and `clear.wav` are project-owned procedural audio. The other 24
use project-authored prompts and ElevenLabs-generated output, subject to the
account's agreement; they are not represented as CC0, public domain, or
unrestricted stock.
[ElevenLabs' Sound Effects terms (Exhibit 4)](https://elevenlabs.io/creative-terms)
allow embedding output with other material in games, subject to the applicable
plan, and restrict making isolated audio files or sound libraries available.
[Commercial use requires an eligible plan](https://help.elevenlabs.io/hc/en-us/articles/13313564601361-Can-I-publish-the-content-I-generate-on-the-platform).
The MCP does not expose proof of this account's plan. The generating account
owner's earlier confirmation covered the previous 21 mastered WAVs only; it has
not yet been recorded for this 26-file set, so the owner must confirm it before
this change is merged. Raw takes stay private either way, and inclusion in this
repository does not grant unrestricted redistribution rights.

Automated checks cover regeneration, procedural-cue preservation, WAV format,
duration tiers, selected-metadata agreement, non-silence, peak headroom,
zero-valued endpoints and `pubspec.yaml` registration. They cannot establish
whether a cue sounds good, is distinct from its neighbours, or stays intelligible
under rapid 1x/3x repetition in a real mix; that has **not** been verified. Treat
perceptual quality as unverified until someone listens on a representative device
with the playback integration.
