### Storage-failure injection (real browser, no test hooks)

- `Storage.prototype.setItem` was overridden to throw
  `QuotaExceededError` before the wave-8 victory of the third full run
  (played live like the others: Rocket Fusing, Heavy Caliber, Overclock
  Relay drafts; same deploy/upgrade order).
- Victory report rendered normally but showed **`Save failed — progress
  unchanged.`**, `Saved best retained: Gold • 20 base health`,
  `Scrip not credited`, `Retry Save to keep this 150 Scrip award.`, and
  buttons `Retry Save` / `World Map (Unsaved)`. The committed save stayed
  `scrip:235` — unchanged.
- After restoring `setItem`, `Retry Save` flipped the report to `Result
  saved. Best medal unchanged.` + `Scrip credited: 150`; the persisted
  save became `scrip:385` — exactly one award, no double credit.
- Flare transaction failure (same injection): tapping `FIRE FLARE · 100`
  surfaced `Could not save campaign progress.`, balance stayed 385, no
  draw committed; after restore the purchase succeeded (385 -> 295).
- Level Up transaction failure (same injection): `LEVEL UP · 60` surfaced
  `Could not save campaign progress.`, Mio stayed LV 1, balance stayed
  295; after restore the level-up committed (Mio LV 2, 235).
- `Storage.prototype.setItem` was fully restored after each check; the
  injected quota errors never reached unrelated keys.

## Text-scale coverage

Browser text-scale at 2x is not reachable on Flutter web (the platform
dispatcher fixes textScaleFactor at 1.0). Coverage is deterministic:
`test/widget/stage_briefing_sheet_test.dart` pumps the sheet at 320 x 568
with 1x, 1.5x and 2x `MediaQuery.textScaler` and asserts every Scrip label
renders whole (no ellipsis, single text box). These failed before the fix
(`FIRST CLEAR` truncated at both scales) and pass after.

## Deviations and blockers

- **MCP profile lock:** `new_page`/`list_pages` initially failed because
  Chrome was already running on the MCP default profile
  (`chrome-profile`); the server recommends `--isolated` for parallel
  instances. Work continued on the already-open page, which reports
  `isolatedContext=hpa-923-task7-acceptance`. Storage writes were confined
  to this context; unrelated keys were enumerated and preserved.
- **Screenshot filePath:** MCP `take_screenshot`/`evaluate_script` cannot
  write inside the repo (outside configured workspace roots). Committed
  artifacts therefore come from the `ORION_CAPTURE_DIR` widget-capture
  path (`hpa-923-evidence/fixture-1b.png`); all browser screenshots were
  captured and inspected inline.
- **Compact fix not present during first live run:** the running debug
  server predated the fix, so the pre-fix truncation was reproduced live
  (valuable: it confirmed the defect). DTD `hot_reload` then applied the
  fix and the 320 x 568 capture was retaken showing the collapsed layout.
- **2x text scale in browser:** unreachable on Flutter web; covered by the
  widget regression tests noted above.
- **Game speed in automation:** waves were played at 2x/3x; ~2-3 minutes
  wall time each in the emulated page.
- Fresh-profile `0 Scrip` Flare screen was not re-opened after funds were
  earned; the identical underfunded disabled state was verified at 385
  (Fire 10) and 85/65 (Level Up) balances.
- Old background-art differences vs the artboards are accepted until
  HPA-926, as recorded in the task ledger.
